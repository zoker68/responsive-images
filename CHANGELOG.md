# Changelog

## 1.3 — 2026-09-25

### Upgrading

- **Two new config keys: `driver` and `extensions`** (`['jpg', 'jpeg', 'png', 'webp', 'gif', 'avif', 'bmp', 'tif', 'tiff', 'heic', 'heif']`). A published `config/responsive-images.php` without them still gets the defaults, since the package config is merged in.
- **The default driver is now Imagick when `ext-imagick` is loaded** (GD otherwise, as before). On such servers new images are generated by Imagick: animated GIFs stay animated, TIFF/HEIC are converted, and queue workers need more memory, which `memory_limit` does not cap. Files already generated by GD keep being served until `php artisan responsive-images:clear`. Set `RESPONSIVE_IMAGES_DRIVER=gd` to keep GD.
- **SVG and other files outside `extensions` are no longer converted.** Neither is a listed format that the driver on this server cannot read (AVIF without libavif, TIFF/HEIC with GD). They are rendered as a plain `<img>` pointing to the original on the source disk.
- **Animated GIFs become static with the `gd` driver** (it writes only the first frame). Switch to `imagick` or remove `gif` from `extensions` if you serve animated GIFs.
- **`<source>` is rendered only for generated images in the output format.** Before generation the original is rendered as a single `<img>`. Custom copies of `picture.blade.php` or `components/responsive-image.blade.php` should wrap `<source>` in `@if ($hasSource)` / `@if ($image->hasSource())`.
- **Run `php artisan responsive-images:clear` after deploying.** Cached `make()` results written by 1.2.x hold the old fallback shape and can render a stray `<source … 100w>` until they expire (`cache_ttl[1]`).
- **`cache_store` falls back to `CACHE_STORE`**, not the removed `CACHE_DRIVER`. Set `RESPONSIVE_IMAGES_CACHE_STORE` explicitly if you relied on `CACHE_DRIVER`.

### Added

- **`extensions` config option.** Extensions are compared case-insensitively, so `PHOTO.JPG` counts as `jpg`. For an unsupported file `make()` returns a `ResponsiveImage` with `src` = URL of the original, empty `generatedImages`, `width`/`height` as passed (or `0`) and `format` = the extension. No job is dispatched. `generate()` returns `null` and writes nothing.
- **GIF, AVIF and BMP sources** are converted to WebP along with JPEG, PNG and WebP.
- **`driver` option: `gd` or `imagick`** (`RESPONSIVE_IMAGES_DRIVER`, enum `Enums\ImageDriver`). Imagick keeps GIF animation in the WebP output and reads TIFF and HEIC. `ext-imagick` is listed under `suggest`. Run `responsive-images:clear` after switching: file names do not depend on the driver.
- **Displayable fallback for TIFF and HEIC.** Browsers cannot show these originals, so before the job has run `make()` converts the full-size WebP synchronously and returns it. A failed conversion is reported and falls back to the original URL.
- **`ResponsiveImage::hasSource()`**: `true` when there are generated images in the output `format`. Both templates use it.
- **Test suite** (PHPUnit + Orchestra Testbench), runnable from the package directory (`autoload-dev` added).

### Fixed

- **Generation works on `intervention/image` 4.** The code paths labelled v4/v3 actually targeted v3/v2, so `generate()` failed on v4 (`ImageManager::read()` does not exist there). Images are now decoded with `decodeBinary()` on v4 and `read()` on v3, and encoded with `encode(new WebpEncoder(...))` on both.
- **No job on every cache refresh for SVG and other formats GD cannot read.** Previously `GenerateResponsiveImages` was dispatched and failed every time `flexible()` revalidated the entry.
- **Correct `type` on `<source>`.** The fallback produced `type="image/svg"` and `type="image/jpg"`. There is no `<source>` for the original any more.
- **No `0w` in `srcset`.** The fallback for `make()` without a width stored `[0 => url]`. It is now empty, and `getSrcset()` skips widths ≤ 0.
- **`getImage()` returns `src` when nothing has been generated** instead of failing on a `null` key.

## 1.2.1 — 2026-05-27

### Fixed

- **`make()` caches a plain array instead of the `ResponsiveImage` object** and rebuilds the object on read.

## 1.2 — 2026-05-27

### Added

- **`make()` results are cached with `Cache::flexible()`** (stale-while-revalidate). Configured with `cache_store` and `cache_ttl` (`[stale, expire]`).

## 1.1 — 2026-05-27

### Added

- **Background generation.** `make()` returns a fallback immediately and dispatches `GenerateResponsiveImages` to build the missing sizes. The `queue` option sets the queue name.
- **`ResponsiveImage` getters**: `getImages()`, `getImage($width)`, `getSrcset()`.

## 1.0 — 2026-05-26

- First release: WebP conversion and responsive sizes by breakpoints, `ResponsiveImages` facade, `<x-responsive-image>` component, `@responsiveImage` directive, `responsive-images:clear` command. Supports `intervention/image` 3 and 4.
